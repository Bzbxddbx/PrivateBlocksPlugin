# PrivateBlocksPlugin

Плагин для Paper (1.21+) — защита территории от других игроков с использованием специальных «приват-блоков».

## Возможности

- **4 вида приват-блоков** с разным размером защищаемой территории:

  | Блок            | Размер территории |
  |-----------------|-------------------|
  | Золотой блок    | 7×7×7             |
  | Алмазный блок   | 9×9×9             |
  | Изумрудный блок | 15×15×15          |
  | Незеритовый блок| 21×21×21          |

- **Полная защита территории:** чужие игроки не могут ни ломать, ни ставить блоки внутри зоны привата.
- **Правило «нет пересечений»:** новый приват-блок нельзя установить, если его зона пересекается с любой существующей.
- **Снятие привата:** владелец ломает центральный блок (сам приват-блок) — приват снимается; периферию территории владелец ломает свободно.
- **Настраиваемость:** материалы и размеры меняются в `config.yml` без пересборки плагина.
- **Персистентность:** все приваты сохраняются в SQLite и переживают рестарт сервера.
- **Автовосстановление блоков:** при старте плагин проверяет, что центральный блок каждого привата на месте, и возвращает его, если блок пропал (например, после жёсткого рестарта до сохранения чанка). Отключается в `config.yml`.

## Установка

1. Соберите плагин: `mvn package`.
2. Скопируйте `target/PrivateBlocksPlugin-1.jar` в папку `plugins` сервера.
3. Перезапустите сервер.

## Конфигурация

`plugins/PrivateBlocksPlugin/config.yml`:

```yaml
restore-missing-blocks: true

claims:
  EMERALD_BLOCK: 15
  DIAMOND_BLOCK: 9
  NETHERITE_BLOCK: 21
  GOLD_BLOCK: 7
```

- `restore-missing-blocks` — если `true` (по умолчанию), при старте плагин автоматически ставит обратно приват-блок, если его нет на месте центра привата.

Значение — размер стороны куба (должно быть нечётным числом ≥ 1). Чтобы добавить новый приват-блок, достаточно добавить строку вида `MATERIAL: размер`. Для игрового материала используется его имя из `Material` (например, `IRON_BLOCK: 11`).

Если секция `claims` отсутствует или не содержит ни одного валидного тира, применяются встроенные значения по умолчанию (таблица выше).

## Хранение данных

Приваты хранятся в базе SQLite: `plugins/PrivateBlocksPlugin/claims.db`.

- **Запуск:** при старте база однократно читается в in-memory кэш до начала игровых событий.
- **Игровой процесс:** чтение всегда идёт из кэша (мгновенно), а каждая запись (создание/удаление привата) выполняется асинхронно в отдельном потоке записи.
- **Выключение:** перед остановкой сервера `onDisable` синхронно дожидается завершения всей очереди записи (`awaitTermination`), что гарантирует: ни одно изменение не потеряется при рестарте.
- **Стартовый health-check:** после загрузки базы плагин сверяет блок в центре каждого привата с ожидаемым материалом (тир определяется по радиусу) и при расхождении возвращает блок на место. Действует только на центр привата, не трогает территорию.

## Техническая архитектура

```
PrivateBlocksPlugin/
├── PrivateBlocksPlugin.java      // composition root: DI, жизненный цикл БД
├── block/
│   ├── Claim.java                // домен: владелец, центр, радиус; contains/intersects
│   ├── BlockKey.java             // value-object (worldId, x, y, z) вместо Location
│   ├── ClaimManager.java         // сервис операций с приватами (depends on ClaimRepository)
│   ├── ClaimBlockRestorer.java   // автовосстановление приват-блоков на старте
│   ├── ClaimCreateResult.java    // SUCCESS / OVERLAPS
│   └── repository/
│       ├── ClaimRepository.java  // интерфейс хранилища
│       ├── SqlClaimRepository.java // кэш + асинхронная запись в SQLite
│       └── sqlite/
│           └── ClaimDao.java     // низкоуровневый JDBC
├── config/
│   ├── PluginSettings.java       // чтение и валидация config.yml
│   └── ClaimTier.java            // value-object (material, radius)
├── command/
│   └── PrivateBlocksCommand.java // /pbhelp
└── listener/
    └── BlockProtectedListener.java // события BlockPlace/BlockBreak
```

### Почему это чистая архитектура (SOLID)

- **S (единственная ответственность)** — каждый класс решает одну задачу: `Claim` — геометрия региона, `ClaimManager` — бизнес-операции, `ClaimDao` — только JDBC, `PluginSettings` — только конфиг, листенер — только перевод событий в вызовы сервиса.
- **O (открыт-закрыт)** — новые приват-блоки добавляются строкой в `config.yml`; расширение поведения не требует правки кода.
- **L (подстановка Лисков)** — `ClaimRepository` без побочных эффектов; на его месте может быть любая реализация без изменения логики.
- **I (разделение интерфейсов)** — `ClaimRepository` — узкий интерфейс ровно с теми методами, которые нужны потребителю.
- **D (инверсия зависимостей)** — `ClaimManager` и листенеры зависят от абстракции `ClaimRepository` и `PluginSettings`, а не от конкретных реализаций. Замена SQLite на MySQL/PostgreSQL или файловое хранилище — это один новый класс и одна строка в composition root.

### Производительность

- Чтения в событиях выполняются из in-memory кэша — игровой поток никогда не блокируется на I/O.
- Записи уходят в БД асинхронно одним потоком — сериализация оправдана (небольшой трафик) и исключает состояние гонки на соединении.
- Поиск по территории линейный по числу приватов (достаточен для небольших серверов); при росте нагрузки легко заменить на chunk-индекс внутри `SqlClaimRepository`, не трогая остальных.
